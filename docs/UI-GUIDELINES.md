# UI 视觉与语义规则

> 状态：已定稿并落地  
> 更新日期：2026-08-12  
> 依据：[UI 现状盘点](./UI-AUDIT.md)

本文件定义番茄记账 UI 调整的共同方向，并与 `miniprogram/app.wxss` 中的 Token、公共组件及自动检查共同构成后续任务的执行基线。

## 一句话方向

番茄记账是一个温暖、清晰、耐看的生活记账工具：保留番茄色辨识度，优先保证数据和操作清楚，不让装饰压过内容。

## 基础原则

1. 维持现有暖色背景、番茄主色、大圆角和线性图标方向，不重新设计品牌风格。
2. 页面依靠留白、文字、颜色、边框和背景建立层级，默认完全不使用阴影。
3. `tl-tabbar` 是唯一允许使用阴影的常规组件；阴影必须轻、柔和、向上，只用于和页面内容区分。
4. 渐变只用于页面背景或少数重点区域，方向单一、同色系、深浅连续，结束颜色必须与相邻底色自然衔接。
5. 页面可以存在多个重要内容，但同一视区不能出现多个视觉强度完全相同的焦点。
6. Hero 不是页面标配；只有内容确实需要形成主焦点时才使用。
7. 统一的是视觉语义和交互预期，不强迫不同业务页面共用相同布局。

## 页面组织方式

页面从外到内按照以下顺序组织：

1. **留白划分模块**：页面级模块优先通过间距和标题区分。
2. **模块内部确定重点**：通过位置、字号、数字尺度和少量颜色表达主次。
3. **必要时使用卡片**：只有内容需要独立边界、整体操作、状态承载或背景区分时才添加容器。
4. **同类内容使用分隔线**：列表、设置项、成员和账户等连续内容在同一容器内部通过细线或间距区分。

不使用分隔线切割页面级模块，也不为了丰富画面把每个模块放进卡片。

## 页面内容层级

| 层级       | 职责                           | 规则                                        |
| ---------- | ------------------------------ | ------------------------------------------- |
| 页面上下文 | Navbar 标题、返回和必要操作    | 只说明当前位置，不承载业务内容              |
| 关键内容   | 当前页面的重要数据、任务或状态 | 可以有多个重点，但必须有强弱关系；Hero 可选 |
| 主要内容   | 列表、表单、图表和设置项       | 通过模块标题、留白和必要容器组织            |
| 辅助信息   | 说明、时间、提示和次要统计     | 在字号、颜色和位置上弱于主要内容            |
| 底部能力   | 导航、提交、弹层或键盘         | 由单一公共能力负责布局和安全区              |

## 视觉语义矩阵

### 按钮

| 角色     | 典型场景                   | 视觉要求                                     |
| -------- | -------------------------- | -------------------------------------------- |
| 主操作   | 保存、确认创建、提交、完成 | 当前操作区域最高强调；同一区域原则上只有一个 |
| 次操作   | 取消、稍后处理、返回上一步 | 明显弱于主操作，不与主操作争夺注意力         |
| 危险操作 | 删除、退出、移除成员       | 使用危险语义，不借用普通主操作样式           |
| 文字操作 | 重试、查看全部、编辑、管理 | 融入内容，不制造额外色块                     |
| 图标操作 | 关闭、更多、局部编辑       | 必须有清晰图标语义和足够点击区域             |

统一要求：

- 按钮统一管理默认、按下、禁用和 Loading 状态。
- Loading 时保持原有宽高，避免内容抖动，并阻止重复提交。
- 普通按钮不使用阴影；层级通过填充色、浅色背景、边框或文字表达。
- 同一操作不要同时在内容区和底部能力区重复出现。
- 不按页面名称创建新的按钮视觉；先映射到现有语义角色。

### 卡片与承载区域

| 角色       | 使用条件                         | 不应承担的职责               |
| ---------- | -------------------------------- | ---------------------------- |
| 基础内容卡 | 一组内容需要独立边界或背景区分   | 不用于包装每个普通模块       |
| 数据卡     | 一组数据需要作为整体理解         | 不把每个统计数字分别卡片化   |
| 操作卡     | 整块内容可点击或包含明确局部操作 | 不替代普通列表行             |
| 状态卡     | 结果、权限或业务状态需要整体承载 | 不强制用于所有 Empty / Error |
| 图表容器   | 图表需要稳定绘制背景和内边距     | 不统一图表内部业务布局       |

统一要求：

- 卡片不使用阴影，通过背景、细边框和留白建立边界。
- 同一页面的同级卡片使用一致圆角、边框和内边距。
- 不嵌套视觉强度相同的卡片；内部区域优先使用留白或弱背景。
- 卡片可以包含重点内容，但“重点”不等于必须使用卡片。

### 标题、正文与数字

| 角色     | 作用                   | 规则                                   |
| -------- | ---------------------- | -------------------------------------- |
| 页面标题 | 说明当前页面           | 由 Navbar 统一表达                     |
| 模块标题 | 划分页面级内容         | 清晰但不抢关键数据焦点                 |
| 容器标题 | 说明卡片或图表内容     | 弱于模块标题                           |
| 正文     | 主要信息和列表内容     | 保持稳定可读性                         |
| 辅助文字 | 描述、时间、提示和单位 | 使用次级颜色，不依赖过小字号弱化       |
| 关键数字 | 金额、比例和核心统计   | 通过字号、字重和位置突出，颜色只作辅助 |

统一要求：

- 不为相近语义创建连续的 `23rpx`、`24rpx`、`25rpx` 等局部字号。
- 同一级文字在不同页面保持相同字号、字重、行高和颜色语义。
- 番茄红不用于大段正文；收入、支出、危险和品牌强调分别遵循对应语义。
- 数字与单位形成稳定强弱关系，避免单位和金额同等突出。

### 表单

| 层级       | 包含内容                 | 规则                                       |
| ---------- | ------------------------ | ------------------------------------------ |
| 表单分组   | 同一业务目的的字段       | 通过标题和留白分组，必要时使用一个承载区域 |
| 字段       | 标签、输入、说明和错误   | 结构、间距及状态保持一致                   |
| 选择型字段 | 分类、账户、日期和图标等 | 外观和点击反馈与输入型字段同体系           |
| 提交能力   | 保存、创建、导入等       | 进入页面操作区，不在页面内重复固定实现     |

统一要求：

- 输入框本身不是卡片，不为每个字段增加大型圆角容器。
- 聚焦、已填写、禁用、只读、错误状态必须可区分。
- 标签、占位符、实际值、说明和错误信息保持稳定层级。
- `tl-record-form` 继续管理记账领域组合和数字键盘，不拆成页面局部实现。

### 列表

| 角色     | 典型场景           | 规则                                 |
| -------- | ------------------ | ------------------------------------ |
| 数据列表 | 收支记录、反馈记录 | 强调扫描效率和主次信息               |
| 功能列表 | 设置、功能入口     | 统一行高、图标、标题、说明和尾部提示 |
| 管理列表 | 成员、账户、分类   | 保留状态和操作权限表达               |
| 层级列表 | 分类树等           | 允许业务化缩进和展开关系             |

统一要求：

- 同类项目共享一个列表区域，项目之间使用细分隔线或稳定间距。
- 不默认把每一行做成独立卡片。
- 列表行保持稳定的左侧识别区、中部信息区和右侧状态或操作区。
- 最后一项不保留无意义的尾部分隔线。
- 空列表进入统一 Empty 状态，不渲染空白列表外壳。

### Loading / Empty / Error / Ready

页面数据状态统一为互斥状态链：

```text
loading → error / empty / ready
```

| 状态    | 规则                                                         |
| ------- | ------------------------------------------------------------ |
| Loading | 首次数据加载优先使用 `tl-skeleton`；局部提交使用按钮 Loading |
| Empty   | 使用 `tl-empty-state`，只提供与空状态直接相关的操作          |
| Error   | 提供简洁原因和明确重试入口，不与 Empty 混用                  |
| Ready   | 只在数据准备完成后渲染真实内容                               |

统一要求：

- Loading 时不得提前渲染 Ready 内容，避免骨架与真实元素同时出现。
- 全局阻断式 Loading 仅用于必须等待的流程；文案由调用方传入，可在流程中更新。
- 骨架只覆盖将被真实内容替换的区域，不模拟 Tabbar、Navbar 等稳定壳层。
- 状态切换不得改变页面壳层和底部区域的位置。
- 页面级、模块级和按钮级 Loading 必须明确归属，避免多套 Spinner 同时出现。

### 底部能力与浮层

| 能力              | 负责内容                                | 安全区归属         |
| ----------------- | --------------------------------------- | ------------------ |
| `tl-tabbar`       | Tab 导航、中央记账入口和 Tab 页附属操作 | Tabbar 统一负责    |
| `tl-page-actions` | 非 Tab 页的保存、提交、创建等操作       | 页面操作区统一负责 |
| `tl-bottom-sheet` | 账本切换、选择器和底部确认弹层          | Sheet 面板统一负责 |
| `tl-record-form`  | 数字键盘、金额输入和记录提交联动        | 记录表单统一负责   |

统一要求：

- 同一时刻只能有一个底部能力负责安全区。
- 内容区只预留当前底部能力所需高度，不重复增加安全区。
- Tab 页的固定操作进入 Tabbar 提供的操作区域，不独立覆盖 Tabbar。
- 非 Tab 页的固定按钮进入 `tl-page-actions`。
- Bottom Sheet 打开时覆盖页面底部能力，并自行处理遮罩、面板和安全区。
- 居中 Dialog 不属于底部能力，不因安全区额外抬高。
- 浮层通过遮罩、背景和边框建立层级，不使用阴影。
- Toast 使用 success / warning / error / info 语义；warning 使用暖橙色，只提示可继续但需注意的情况。
- 数字键盘属于特殊领域交互，由 `tl-record-form` 保持内部事件闭环。

### 公共组件边界

| 组件               | 负责内容                                                                          |
| ------------------ | --------------------------------------------------------------------------------- |
| `tl-container`     | 页面内容壳层及普通页面安全区                                                      |
| `tl-skeleton`      | 页面或模块首次加载骨架，不包含稳定的 Navbar / Tabbar 壳层                         |
| `tl-empty-state`   | Empty 与可重试 Error 的通用呈现                                                   |
| `tl-button`        | 主、次、危险、文字按钮及 Loading / Disabled 状态                                  |
| `tl-page-actions`  | 非 Tab 页固定操作及底部安全区                                                     |
| `tl-bottom-sheet`  | 底部弹层、遮罩和底部安全区                                                        |
| `tl-dialog`        | 居中结果、确认或提示浮层                                                          |
| `tl-feedback-host` | 统一订阅反馈服务，内部呈现阻断 Loading 与 success / warning / error / info 短提示 |
| `tl-tabbar`        | Tab 导航、中央记账入口及 Tab 页底部安全区                                         |
| `tl-record-form`   | 记账领域表单、金额输入、数字键盘及提交联动                                        |

页面负责业务数据和事件，不重复实现上述通用视觉、定位或安全区能力。公共组件之间不直接访问页面数据，通过属性和事件保持单向交互。

全局反馈通过 `services/feedback-ui` 调用。阻断式 Loading 返回标识，调用方在 `finally` 中按标识关闭；流程文案变化时使用 `updateLoading`。Toast 接受 `type` 与 `message`，新提示替换当前提示。

```javascript
const loadingId = feedback.showLoading({ message: "正在准备数据…" });
try {
  feedback.updateLoading(loadingId, { message: "正在下载数据…" });
} finally {
  feedback.hideLoading(loadingId);
}
feedback.showToast({ type: "warning", message: "部分数据未导入" });
```

## 页面类型应用

| 页面类型     | 重点                                     | 分区建议                                 |
| ------------ | ---------------------------------------- | ---------------------------------------- |
| 首页         | 当前账本状态、关键收支数据、主要记账入口 | 概览可形成重点区域，最近记录使用连续列表 |
| 明细页       | 筛选条件、日期分组、记录流               | 列表优先，不强行增加 Hero 或逐条卡片     |
| 分析页       | 时间范围、关键统计、图表                 | 数据与图表分层，图表允许独立承载区域     |
| 我的页       | 身份、账本入口和功能设置                 | 功能列表保持清晰扫描，不堆叠装饰卡片     |
| 表单页       | 当前填写任务和提交状态                   | 字段按业务分组，底部提交进入公共操作区   |
| 设置与管理页 | 分组、权限、当前状态                     | 同类项目共享容器，危险操作与普通设置分离 |
| 登录页       | 品牌识别与进入动作                       | 保留独立品牌布局，不强行套普通页面壳     |

## 合理例外

以下场景可以保留业务化布局，但仍须遵守颜色、文字、间距、状态和无阴影规则：

- 登录页品牌展示。
- 首页、明细、分析、我的四个 Tab 的不同信息结构。
- 分析图表、记录时间流和分类树。
- 记录编辑的数字键盘、金额输入和提交联动。
- 权限、危险操作、导入结果等需要明确提示的业务状态。

例外只允许解决业务结构差异，不能成为新增相近颜色、字号、圆角、阴影或按钮体系的理由。

## 禁止写法

- 除 `tl-tabbar` 外新增 `box-shadow` 或 `filter: drop-shadow()`。
- 使用端点无法衔接页面底色的渐变，或在普通组件中堆叠多层渐变。
- 每个页面自行创建主按钮、固定底部栏、空状态、骨架或通用 Sheet。
- 使用隐藏 Tabbar 作为普通页面的安全区占位。
- 同一页面混用多套同级卡片圆角、按钮高度或标题层级。
- 卡片层层嵌套，或把每条列表项做成独立卡片。
- Loading、Empty、Error 与 Ready 内容同时渲染。
- 仅为了页面“更丰富”增加无业务含义的元素、色块或装饰。

## 后续任务的验收方式

每次 UI 任务至少检查：

1. 是否符合本文件的一句话方向和基础原则。
2. 页面模块是否按照留白、重点、必要卡片、同类分隔组织。
3. 新元素是否能映射到已有视觉语义，而不是创建页面私有体系。
4. 是否遵守无阴影规则和渐变衔接规则。
5. Loading、Empty、Error、Ready 是否互斥且归属明确。
6. 底部能力及安全区是否只有一个负责人。
7. 是否删除了不承担信息、交互或状态职责的元素。

## 自动检查与视觉回归

- `npm run ui:check`：检查阴影、渐变、页面级固定定位、安全区、私有 Spinner、原生 Toast/Loading 调用、硬编码字号/圆角、未定义 Token 和 WXML 标签闭合；存量允许清单必须保持为 0。
- `npm run visual:check`：将关键页面截图与已确认基线对比，发现非预期视觉变化时失败。
- `npm run visual:update`：只在视觉变更已人工确认后更新基线，不用它掩盖差异。
- 视觉脚本依赖微信开发者工具开启“设置 → 安全设置 → 服务端口”；工具路径不同时通过 `TL_WECHAT_CLI` 指定。

新增 UI 时优先复用 `app.wxss` 的语义 Token。确需新增 Token 或公共组件能力时，先确认它可被多个页面用同一语义解释，再同步更新本文件和自动检查。

### 组件注册与账本选择

- 全局注册仅保留通用基础组件；Tab 内容、Tabbar、预算条、分类树、记录表单、账本选择器和图表在使用处注册。
- tl-ledger-switcher 统一账本选择弹层、加载、失败重试和选中状态，只发出选择事件。首页负责激活账本；明细与分析页只更换查看范围。
- tl-budget-progress 只接收 enabled 和 rate，将显示宽度限制在 0–100%；预算金额和剩余金额由业务数据提供。
- tl-skeleton 支持 home / records / list / detail / analysis，缺省或未知类型回退为 list。
