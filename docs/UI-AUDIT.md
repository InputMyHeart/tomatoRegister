# UI 现状盘点

> 盘点日期：2026-08-12  
> 盘点范围：`miniprogram/` 下的业务页面与 `tl-*` 组件，不包含第三方 `ec-canvas`。  
> 状态：UI 收敛前的历史基线；当前规则见 [UI 视觉与语义规则](./UI-GUIDELINES.md)。  
> 本文主体记录改造前现状和收敛候选，不作为当前实现说明。

## 结论

项目已经形成清晰的视觉方向：番茄主色、暖色背景、大圆角卡片和 Remix Icon 线性图标基本稳定。当前问题不是“没有风格”，而是同一语义被多套局部样式表达，导致页面越多，维护和校准成本越高。

下一阶段不应选择某个页面作为全局视觉标准，而应先确定按钮、卡片、标题、表单、列表、状态和浮层各自承担的语义，再让首页、明细、分析及二级页面共同映射到同一套规则。

## 七类视觉元素

### 1. 按钮

- 已有全局 `.tomato-button` 和 `.ghost-button`，但页面仍出现 `.primary-action`、`.save-button`、`.primary-button`、`.submit-button`、`.create-button`、`.import-button`、`.login-button` 等多套实现。
- WXML 中可识别出 53 个带按钮或操作语义的类名；其中 `.primary-action` 出现 9 次，`.tomato-button` 出现 8 次，说明全局样式并未成为唯一入口。
- 保存加载动画 `saveButtonSpin` 在 3 个页面重复定义，其他提交、登录、加入和重试按钮又分别维护自己的 Spinner。

收敛候选：先定义主操作、次操作、文字操作、危险操作、图标操作五种语义，以及默认、按下、禁用、加载四种状态；是否抽组件在语义确定后决定。

### 2. 卡片

- 全局 `.card` 已使用 39 次，是目前复用最成功的视觉原语。
- 仍可识别出 63 个带卡片、面板、概览或 Hero 语义的类名，例如 `state-card`、`detail-card`、`summary-card`、`setting-card`、`chart-card`。
- 26 种圆角和 41 种阴影表明“卡片”仍混合了承载内容、突出数据、反馈状态和可点击入口等不同职责。

收敛候选：区分基础内容卡、强调数据卡、可操作入口卡、状态卡；图表容器只共享表面规则，不强行共享内部布局。

### 3. 标题与文字层级

- 共使用 29 个字号，`22rpx`、`23rpx`、`24rpx`、`25rpx`、`26rpx`、`27rpx`、`28rpx`、`29rpx`、`30rpx` 连续存在。
- 高频语义包括 `field-label`、`section-title`、`detail-label`、`card-title`，但同名或近义类并未映射到稳定字号、字重和颜色。
- 全局已声明 3 个字号 Token，但目前业务样式几乎仍在直接写值。

收敛候选：建立页面标题、分区标题、卡片标题、正文、辅助说明、数字强调六级语义；金额与统计数字允许单独的数字层级。

### 4. 表单

- 普通页面仍分别维护输入框、选择器、文本域、字段标签和表单卡片样式。
- `tl-record-form` 已集中管理记账表单、快捷金额、标签和数字键盘，这是合理的领域封装，不应拆回通用表单。
- 当前缺少统一的字段高度、标签间距、边框、聚焦、禁用、错误和说明文本规则。

收敛候选：先统一字段容器与状态外观；业务组合继续由页面或领域组件负责。

### 5. 列表

- 列表实现包含功能入口、账本、成员、账户、分类、记录、反馈等业务类型。
- `tl-member-list` 是目前唯一广泛使用全局 Token 的组件，但仅覆盖成员列表。
- 行高、左右间距、分隔线、图标容器、尾部操作和空列表占位仍由各页面决定。

收敛候选：定义基础列表行结构和密度，保留记录流、分类树、成员权限等业务化差异。

### 6. Loading / Empty / Error / Ready

- `tl-skeleton` 已统一首页、明细、分析三个 Tab 的首次数据加载，并且由内容区控制，Tabbar 不参与骨架渲染。
- `tl-empty-state` 共 9 个实例，覆盖首页、明细、反馈历史、账本设置和记录详情中的部分空状态。
- 其他页面仍使用独立 Spinner、加载卡片、文字提示或按钮内 Loading；错误与重试入口也存在多种形态。
- 当前状态命名和渲染优先级未形成统一契约，容易出现 Loading 与 Ready 内容同时显示。

收敛候选：统一为 `loading → error / empty / ready` 的互斥状态链；骨架、空态和错误态使用公共组件，按钮 Loading 作为按钮状态处理。

### 7. 底部区域与浮层

- 7 个页面自行使用固定定位：`category-operation`、`ledger-create`、`ledger-settings`、`member-manage`、`payment-account`、`record-category`、`record-import`。
- 其中底部操作条至少有 `create-bar`、`ledger-bottom-actions`、`account-add-bar`、`category-action` 四种；自建浮层包括编辑 Sheet、结果 Sheet、分享 Sheet 和导入结果遮罩。
- 公共 `tl-page-actions` 与 `tl-bottom-sheet` 已存在，但尚未覆盖这些页面实现。
- `tl-record-form` 的固定提交区、删除区、键盘和键盘遮罩是高耦合交互，应由记录表单领域组件继续管理。

收敛候选：Tabbar 只管理 Tab 导航；普通页面底部操作交给 `tl-page-actions`；通用浮层交给 `tl-bottom-sheet`；数字键盘和记录提交区留在 `tl-record-form`。

## Token 使用现状

`app.wxss` 已声明 21 个颜色、间距、圆角、字号、阴影和层级 Token，但落地范围很小：

- `tl-member-list` 已系统使用 Token。
- 全局 `.card`、`.tomato-button`、`.ghost-button` 自身仍直接写具体值。
- 大部分页面和组件继续硬编码颜色、间距、圆角、字号与阴影。
- `#fff` 与 `#ffffff`、`#25a66a` 与 `#2f9d68`，以及多组暖白色和灰棕色表达接近语义，存在合并空间。

因此，现有 Token 可以作为草稿，不能直接视为已经定稿的设计系统。

## 应保留的合理差异

统一不等于把所有页面做成同一张卡片。以下差异应保留：

- 登录页的品牌展示和进入动效。
- 首页、明细、分析、我的四个 Tab 的信息架构差异。
- 分析图表、记录时间流、分类树等数据结构特有布局。
- 记录编辑的数字键盘、金额输入和提交联动。
- 权限、危险操作、导入结果等业务状态的必要强调。

这些场景应共享颜色、文字、间距、表面、按钮和状态规则，但不必共享同一个业务组件。

## 收敛优先级

1. 先完成视觉语义矩阵，明确七类元素的角色、层级和状态。
2. 再根据矩阵重整 `app.wxss` Token，删除同义值，而不是先批量替换颜色。
3. 明确 `tl-tabbar`、`tl-page-actions`、`tl-bottom-sheet`、`tl-record-form` 的职责边界。
4. 建立 UI 检查脚本和存量允许清单，再开始页面迁移。
5. 页面迁移优先处理壳层、状态链和按钮，之后再统一文字、卡片、表单与列表。

## 本轮未做

- 未修改任何页面 WXML、WXSS、JS 或 JSON。
- 未以首页、预算页或其他单页作为视觉母版。
- 未决定最终 Token 数值、组件 API 或页面迁移顺序。
- 未把扫描统计直接当成错误；品牌页、图表、键盘等特殊值需要在定调阶段逐项确认。
