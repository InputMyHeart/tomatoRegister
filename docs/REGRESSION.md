# 发布前回归清单

每次准备在微信开发者工具上传前，先运行：

```powershell
npm run verify
```

然后在目标测试环境完成与改动相关的手工回归。

涉及 UI 时额外运行：

```powershell
npm run ui:check
npm run visual:check
```

视觉基线只在人工确认变更正确后通过 `npm run visual:update` 更新。

## 核心流程

- [ ] 登录：首次登录、再次进入、退出后重登及当前账本恢复正常。
- [ ] 账本：创建个人/共享账本、切换账本；Owner 编辑名称和备注后当前页面、当前账本缓存及另一成员同步结果正确，非 Owner 无编辑入口且接口拒绝越权。
- [ ] 同步：另一成员修改共享账本记录或分类后，自动同步到期与“我的 → 同步数据”均能刷新当前页面；自动同步无变化时不重复加载业务数据；手动同步即使版本无变化，也重新核对账号、账本和当前账本分类，全部完成后才提示成功。
- [ ] 记录：新增、查看、编辑、删除收入和支出；首页与分析统计同步更新。
- [ ] 首页：收入、支出、结余、本月记录数、支出最多、支出最大和月预算均按当前账本当月全部记录计算；超过 50 条和 100 条时仍与分析页一致。
- [ ] 最近记录：始终显示当前账本全部历史中最新 10 条；当月不足 10 条或无记录时正确跨月、跨年展示。
- [ ] 首页无支出：当月无记录或仅有收入时，“支出最多”和“支出最大”均显示 `-`，不显示默认分类、零金额或 `¥-`；有支出时正常显示。
- [ ] 明细：切换账本、月份和类型筛选；触底分页无重复或遗漏。
- [ ] 分析：月份、年份、全部时间及账本快速切换不会被旧请求覆盖；趋势零值日期完整，支出构成、收入来源、支付账户和共享成员录入图表可触摸查看，排名、预算、环比及无数据状态正确。
- [ ] 预算和账户：权限、禁用、保存与重新进入后的数据恢复正常。
- [ ] 分类：新增、编辑、删除；删除后关联记录迁移到“其他”。
- [ ] 邀请：成员和访客领取正常；写入、编辑、删除、导入和导出权限符合角色规则。
- [ ] 个人资料与反馈：修改后可恢复；反馈创建、图片和历史列表正常。
- [ ] 账本删除：测试环境中验证中断、重试、完成状态及当前账本恢复。

## 组件整理回归

- [ ] 首页选择账本会切换当前账本；明细、分析中的选择只切换查看范围，选中状态、失败重试、账本设置和新建入口正常。
- [ ] Loading 与 Toast 合并后，四种提示、遮罩拦截、重叠请求、页面跳转和返回时的显示及清理正常。
- [ ] 预算条比例为 0、正常值、超预算、异常值时正确显示；各页面骨架及未知类型回退正常。
- [ ] 分析模块：月度趋势与占比、年度收支与近五年结余、分类排名和日历明细均来自接口真实数据；跨年、闰月、空数据及快速切换账本时结果正确，不出现示例记录。

## UI 与状态

- [ ] Loading、Empty、Error、Ready 互斥，不闪现初始化业务数据。
- [ ] 全局 Toast 的 success / warning / error / info 文案、颜色和图标正确；页面跳转后短提示正常消失。
- [ ] 下载模板、删除账本、移除成员和准备分享时，全局 Loading 文案正确，成功或失败后均关闭遮罩。
- [ ] 首屏 Loading 只显示骨架和稳定壳层，不提前显示 Ready 内容或底部业务元素。
- [ ] Tabbar、页面操作栏和 Bottom Sheet 不遮挡滚动内容。
- [ ] 每个页面只有一个底部安全区负责人；刘海屏底部安全区、长文本和窄屏布局正常。
- [ ] Bottom Sheet 遮罩关闭、内部点击、长列表、加载和重试正常。
- [ ] 数字键盘打开、关闭、提交和删除时层级正确，按钮、遮罩与键盘互不遮挡。
- [ ] 除 Tabbar 外无阴影；渐变端点与相邻背景自然衔接。
- [ ] 只读、禁用、保存中和删除中状态与权限一致。

## 正式版额外确认

- [ ] `production.id` 已配置，且同名 `tomatoLedger` 已部署到生产环境。
- [ ] 生产集合、索引和安全规则已核对。
- [ ] 仓库中没有测试数据、用户数据或生产密钥。

## 缓存与数据一致性回归

- [ ] 本地持久化只保留登录资料、账本和分类；登录快照不保存当前账本对象或统计，记录列表不写入本地缓存。
- [ ] 明细月总收入、总支出和笔数来自接口完整汇总；一个月超过 50 条时，首屏 30 条及后续分页均不改变月总数，分页游标正常。
- [ ] 从明细打开编辑再直接返回，原页面已加载记录和位置保留；修改成功后重新查询，最后一条删除后显示空状态。
- [ ] 编辑和详情每次进入均查询最新记录；保存/删除未完成时没有成功提示或返回，失败保留输入并支持重试，冲突不覆盖他人修改。
- [ ] 分析重新进入、切换月份/年份和账目变动时重新读取云端；旧月份的慢请求不会覆盖新月份。
- [ ] 分类冷启动等到真实返回；修改或共享账本版本变化使分类失效，下次读取重新查询；已移除账本的分类一并清除。
- [ ] 手动同步遇到账号、账本或分类任一步失败，不提示成功、不更新成功时间，允许重试；无账本时仍可完成账号和列表同步。
- [ ] 退出、切换账号/环境后分类内存和本地缓存隔离，旧会话未完成的登录/账本/分类请求不得重新写入缓存。
- [ ] 测试环境使用两个微信账号：成员 A 修改共享账目/分类，成员 B 自动同步或手动同步后再进入相关页面，列表与统计保持一致。

## 访客查看记录

- [ ] 访客从首页最近记录或明细进入只读详情，金额、分类、账本、账户、记录人、备注和标签正常显示，无重选分类、保存、删除操作。
- [ ] 明细查看只读账本时，即使当前记账账本可写，点击该记录仍进入只读详情；普通可写账本保持原编辑入口。
- [ ] 底部“＋”始终保留并可点击，初次进入及切换到访客账本后立即置灰，不依赖点击；当前账本只读时提示“当前账本为只读账本，访客仅可查看”，不打开新增流程；切换至可写账本后恢复记账。
- [ ] 通过旧链接直接进入编辑页时，以 `record/get` 返回的角色为准，将访客转到只读详情；加载期间、只读状态下不显示编辑表单和底部操作，不发送保存/删除请求。
- [ ] 测试环境访客直接调用新增、修改、删除接口仍被云端拒绝；成员编辑自己的记录、创建者管理全部记录正常。

- [ ] 记账、导入、预算和快捷金额等因访客权限被拦截时，均使用同一提示“当前账本为只读账本，访客仅可查看”，不出现各入口自定义的不同文案。
