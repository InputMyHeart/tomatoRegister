# 性能与体验优化执行记录

> 更新日期：2026-10-28。本文件记录已在仓库完成的工作与尚未取得的测试环境证据，不将本地模拟测试当作真机性能结论。

## 已完成的本地工作

- 推送优化前仓库基线：`6ba1c13`，`npm run verify` 通过。
- 在 test 环境加入客户端请求耗时与首页、明细、分析内容就绪耗时采样。仅记录路由、页面阶段、状态和耗时，不记录请求内容。
- 分析接口的内部批量读取从 `skip(offset)` 改为 `date`、`createdAt`、`_id` 复合游标；本地测试覆盖同日同时间戳 205 条跨页记录。
- 首页当月指标改为云端分组汇总；最近 10 条仍独立从账本全部历史读取。以空、单笔及 101 条记录的数据对照旧的内存计算结果。
- 云函数调用中断时，前端区分“响应明确失败”和“提交结果未知”；记账、删除及导入提示先核对明细，不自动重发写请求。

## 仍需在 test 云环境和真机完成

1. 准备空、少量、51 条、101 条和较大账本；使用两个测试账号覆盖共享账本。测试数据不写入仓库。
2. 按[实施方案](./EXPERIENCE-OPTIMIZATION-PLAN.md)记录旧版基线与新版在相同设备、网络、账本下的中位及较慢一档耗时。仓库中尚无真实云端耗时数据，因此不能宣称具体提速百分比。
3. 部署优化分支的 `tomatoLedger` 到 **test** 环境，逐项对照首页、明细、分析和云端实际金额；检查聚合算子兼容性、索引命中及云函数内存。
4. 使用断网、慢网和请求中断场景核对写入结果未知的提示与实际记录数量；在两个账号间验证同步、权限与分类迁移。
5. 运行 `npm run verify`、UI 检查及手工回归。确认结果等价、性能改善且没有一致性回归后，再考虑合入发布分支。

## 回退边界

- 若首页聚合与实际云端结果不一致，回退 `dashboard.handler.js` 到逐页计算实现，保留测试账本及差异记录。
- 若分析游标在真实数据上漏读，回退内部读取实现并保存触发问题的脱敏数据形状；对外 `record/list` 协议不变。
- 若性能采样影响界面或日志量，撤销 test 环境采样调用；不影响云端数据。

当前仓库没有自动配置 CloudBase 索引或部署云函数。生产环境尚未创建，本轮不涉及生产数据或生产发布。
