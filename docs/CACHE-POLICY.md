# 缓存与同步规则

## 数据来源

账目和统计以云端为准。首页通过 `ledger/dashboard/get` 读取当月全部数据的汇总与跨月份、跨年份的最近 10 条；明细通过 `record/list` 的 `rangeSummary` 和 `rangeRecordCount` 展示整月统计，不使用已加载页求和代替整月总数。分析每次请求 `ledger/analysis/get`，不复用旧结果。

## 保留的缓存

| 内容             | 生命周期                                  | 更新规则                                                                                      |
| ---------------- | ----------------------------------------- | --------------------------------------------------------------------------------------------- |
| 登录资料         | 本地 `tomatoLedgerAuth`                   | 仅保存用户、OpenID 和环境标识；登录后更新，退出或环境变化时清理，不保存账本对象与统计副本     |
| 账本列表和配置   | 本地 `tomatoLedgerLedgerCache` 与运行状态 | 按环境、账号隔离；前台约 2 分钟检查版本，写入后主动检查                                       |
| 分类             | 本地 `tomatoLedgerCategoryCache` 与内存   | 按环境、账号隔离；冷启动等待查询，有效缓存立即返回，超过 2 分钟等待更新；主动失效后等待新查询 |
| 当前页面的记录   | 页面实例存活期间                          | 保存已加载记录及游标；打开子页面再返回可保留，切换月份/账本、写入成功或发现账本变化后重新查询 |
| 统计及个人页数据 | 当前页面和运行状态                        | 云端查询后展示，不在本地保存；分析无跨页面结果缓存                                            |

已无 `record.store` 和客户端首页计算模块；没有离线写入队列。保存/删除等待云端确认，失败不返回、不丢弃输入。登录、账本和分类保留进行中请求共用；过期结果不能跨会话写回。

## 更新闭环

- 账目创建、编辑、删除、导入成功后，记录服务统一发出更新事件，再检查账本版本；当前展示的首页、明细或分析重新查询云端。
- 分类修改可能迁移账目，因此也通知账目页面刷新。账本同步发现变化使对应分类失效，移除账本同时清除其分类。
- “我的 → 同步数据”依次等待账号信息、账本列表/配置、当前账本分类更新。其他账本分类标记失效；未显示的业务页面下次进入时直接查询云端，无旧记录和分析结果可复用。
- 手动同步不预读未打开页面的全部账目，不把分页账目复制到本地。任一步失败均不提示成功，也不更新完整同步成功时间。
- 个人页显示的同步时间只表示本次运行内最后一次完整手动同步成功时间，与自动账本版本检查时间区分。
- 退出清除登录、账本和分类缓存；内存按会话隔离，旧请求返回后拒绝写回。环境或账号变更不复用上一会话结果。

接口协议、云端权限和数据库字段未改变。按 `REGRESSION.md` 在测试环境完成两账号共享账本及弱网回归后再发布。
